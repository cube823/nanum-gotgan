# 0010 — 사진은 폰 선택기로 받고, 고르는 순서는 우리 화면에서 매긴다

**맥락** — 기획 정의서 58-83~157·70-25~26(Notion 03 등록하기)은 네이티브 앱 기준이다: 사진보관함 권한 팝업(전체 접근/접근 제한/허용 안 함), 권한별 화면(제한 배너·"설정으로 이동"), 앱 안의 최근 사진 그리드, 자체 카메라(플래시·0.5x·전후면), 편집(자르기·회전·그리기). 나눔곳간은 웹앱이다. 웹은 사진보관함 권한 팝업을 띄우거나 보관함 목록을 읽을 수 없다 — 사용자가 폰 선택기에서 고른 파일만 받는다.

**결정** (2026-09-27, 사용자 확인)
- 사진: `<input type="file" multiple>`로 폰 선택기를 열고, 가져온 사진을 우리 그리드(58-157 모양)에 모은다. 누르는 순서대로 번호, 1번이 대표, 최대 10장(Notion·설명 기준 — Figma의 "0/5"보다 우선). 업로드는 "n장 사진 등록하기"를 누를 때, 선택한 것만.
- 권한 팝업·제한·거부 화면(58-83·84·113·114)은 만들지 않는다 — 폰이 대신 처리한다.
- 카메라: 폰 기본 카메라(`capture="environment"`). 자체 카메라 화면(70-26)은 만들지 않는다 — 플래시·0.5x가 브라우저마다 달라 약속을 못 지킨다.
- 편집(자르기·회전·그리기): 이번 범위 밖. `docs/design/MVP.md` "뺀 화면"과 같다.
- 게시물 등록에 **물품 히스토리**(선택, 200자, `items.history`)를 추가. 거래 희망 장소·임시저장·등록 전 미리보기는 이번에 넣지 않는다.

**결과** — 등록 흐름이 모든 폰에서 같게 동작한다. Figma와 달라 보이는 곳(권한 팝업 없음, 편집 버튼 없음, 카메라가 폰 화면)은 이 결정 때문이다. 네이티브 앱(Capacitor 등)으로 감싸면 Figma 그대로가 가능해진다 — 그때 이 결정을 다시 본다.
