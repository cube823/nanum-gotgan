# 0001 — 기관 명단을 시딩하지 않는다

**맥락** — 법적 검토는 "기관 단위 계정 + 담당자 소속 확인(개인 수령 차단)"을 요구한다. 서울시 청년공간 명단을 미리 넣는 방법이 먼저 떠올랐지만, 명단을 받을 경로가 불확실하고 기관은 계속 생기고 없어진다. 관리 주체 없는 마스터 데이터는 썩는다.

**결정** — 자기신고 + 승인. 첫 사용자가 기관을 만들고(manager) 두 번째부터는 자동완성에서 고른다. 기관의 첫 담당자는 운영자가, 그 다음은 같은 기관 verified manager가 승인한다. pending은 조회만 된다.

**결과** — 법적 요구는 "명단의 정확성"이 아니라 "개인 수령 차단"이었고, 그건 승인 기록으로 충족된다. 대신 **기관명 사칭을 막는 건 승인 한 단계뿐**이라 승인 화면에 판단 근거(도메인·이름·시각)를 반드시 보여준다. 이메일 도메인은 보조 신호로만 — 위탁 담당자는 개인 메일을 흔히 쓴다.
