# 0004 — 스키마의 모든 상태는 도달 화면이 있어야 한다

**맥락** — 첫 MVP 범위에서 목록·예약·내리기를 "한 바퀴에 없어도 된다"며 뺐다. 검수에서 드러난 것: 스키마에 `items.reserved`·`withdrawn`, `transfers.scheduled`가 있는데 **거기로 가는 화면이 없었다.** 도달 불가 상태는 없는 상태다. 그리고 스와이프만 있으면 물품 수십 개 서비스에서 며칠이면 피드가 빈다.

**결정** — 셋 다 넣는다. 화면 1개(목록) + 버튼 2개(드리기로 함 / 내리기). `completed`는 반드시 `scheduled`를 거친다 — 예약 없이 완료되면 다른 신청자가 예고 없이 잘린다.

**결과** — `DB-SCHEMA.md` §3에 화살표별 화면 검산표를 두고, **전이를 추가하면 표도 같이** 고치는 규칙이 생겼다. 스와이프(발견)와 목록(재방문)이 역할이 갈렸고, 목록은 `swipes`를 안 본다.

**보강 (2026-09-27)** — 스와이프도 본 것을 빼지 않고 **뒤로 보낸다**(안 본 것 먼저, 본 것은 오래전에 본 순). 빼면 첫 탭이 며칠 만에 늘 빈 화면이 된다. 새로고침으로 기록을 지우는 방식은 버렸다 — 실수 새로고침에 새 물품이 밀린다. `swipes`는 다시 넘기면 시각을 갱신해 순환한다.
