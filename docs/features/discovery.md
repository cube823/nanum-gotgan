# 스와이프 · 목록 · 상세

**무엇**: 다른 기관의 `open` 물품을 발견(스와이프)하고, 다시 찾고(목록), 자세히 본다(상세).
**기획서**: 02 스와이프 탭, 99 물품 제시 화면(= 목록 컴포넌트).

## 두 화면이 있는 이유

스와이프는 본 것을 `swipes`에 기록해 다시 안 보여준다. 물품이 수십 개인 서비스라 며칠이면 피드가 빈다. 그래서 **목록은 `swipes`를 안 본다** — 재방문용 (`decisions/0004`).

## 파일

| | |
|---|---|
| 스와이프 | `web/src/app/(tabs)/swipe/page.tsx` — 20장 프리페치, 터치 60px 임계, 사진 좌/우 탭 넘김 |
| 목록 | `(tabs)/items/page.tsx` + `components/ItemGrid.tsx` (12번 내 정보와 공유) |
| 상세 | `(tabs)/items/[id]/page.tsx` + `ChatButton.tsx` |
| 쿼리 | `web/src/lib/items.ts` — `swipeFeed`, `listFeed`, `getItem`, `CARD` 조각 |
| API | `api/items` GET (`?mode=swipe` 기본 / `?mode=list&category=&page=`), `api/items/[id]` GET, `api/swipes` POST |

## 규칙

- 좌/우 스와이프 = **이전/다음 이동**. 호불호가 아니다. `swipes`에 방향은 없다.
- 스와이프 정렬: **관심 자원(`user_interests`) 먼저, 그 안에서 최신순.** 관심을 안 고른 사용자는
  전부 같은 그룹이라 예전처럼 최신순이다. 목록(`listFeed`)은 관심을 안 본다 — 거긴 카테고리 필터가 있다.
- 우리 기관 물품은 피드·목록 모두 제외 (`org_id <> $my_org`).
- 목록은 `reserved`도 보여준다 — 예약은 깨질 수 있다. 뱃지로 상태만 정직하게.
- `withdrawn`은 API로도 404.
- 상세의 버튼: 내 물품 → "내가 등록한", 같은 기관 → 비활성, 완료 → 비활성, pending → "소속 확인 후", 그 외 → 채팅하기.

## smoke

5 스와이프·목록 (B 피드에 있음 → A 피드엔 없음 → 넘기면 피드에서 빠짐 → 목록엔 남음 → 카테고리 필터)
5b 추천 정렬 (관심 카테고리를 먼저 등록하고 관심 밖을 나중에 등록해도, 관심 쪽이 1번)

## 열린 것

- 거리 표시(`{0}km`)는 뺐다. `lat`/`lng` 컬럼만 있다.
- 20장 다 넘기면 재요청 없이 "전체 목록 보기" 카드. 물품이 많아지면 재요청 필요.
- 실기기 터치 임계값(60px)은 눌러봐야 안다.
- 추천은 관심 카테고리 일치 여부(2단계)뿐이다. 물품이 쌓이면 가중치·최근성 튜닝이 필요할 수 있다.
